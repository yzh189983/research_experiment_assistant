## P0 · 产品化前的必做项

### 1. 登录鉴权与多用户隔离　✅ 已完成（2026-11-16）

> **实现说明**：本条已落地并通过 33 项端到端测试（含 11 条越权攻击测试）。下面保留原规划作为设计对照。

**已实现的能力**

| 能力 | 做法 |
|---|---|
| 账号体系 | `users` 表 + werkzeug PBKDF2 密码哈希；首次启动自动建 `admin`（初始密码加密存于 `data/admin_initial_password.txt`，用 `./rekit admin-password` 查看），也可走 `/register` 自助注册 |
| 双通道登录 | 浏览器用签名 session cookie（`data/secret.key`）；CLI / 脚本用 Bearer API Token（只存摘要，可轮换） |
| 全链路拦截 | 页面 `@login_required`；所有 `/api/*` 由 `before_request` 统一拦截（白名单仅 `/api/auth/login|register`）；WebSocket 握手期校验登录态与主机归属 |
| 数据隔离 | `hosts / experiments / runs / events` 均加 `user_id`；db 层按 `config.current_uid()` 自动过滤；后台线程入口用 `config.as_user(uid)` 显式继承身份 |
| 防越权 | 所有按 ID 访问的 API 都先过 `own_exp_or_404 / own_run_or_404 / own_host_or_404` 校验归属，改代码、看指标、订阅 SSE、删实验、连终端均无法跨用户 |
| 配置隔离 | 系统默认仍在 `config.json`；每用户覆盖存 `data/users/<uid>/config.json`，API Key 等互不可见 |
| 用户管理 | 管理员可在「设置」增删账号、改密码；成员可自行生成 CLI token |
| CLI | 新增 `rekit login / logout / whoami / token`，令牌存 `data/cli_token`（权限 600），可用 `REKIT_TOKEN` 环境变量覆盖；`server_alive()` 改用公开端点探测，避免未登录被误判为服务未启动 |

**P0 安全加固（2026-11-18 已完成）**

- ✅ **HTTPS / WSS**：默认自签证书 + HTTP 308 跳转 + `Secure` Cookie + HSTS
- ✅ **终端安全**：一次性终端票据、Origin 校验、15 分钟空闲 / 4 小时硬超时、只读观察模式
- ✅ **密钥加密存储**：SSH 密码 / 私钥路径、LLM API Key、CLI token、admin 初始密码均加密落盘，存量明文自动迁移
- ✅ **脱敏**：日志、SSE、API 错误响应统一掩码，禁止打印完整 Key

**验收结果**：未登录拦截、登录/登出、token 轮换、建号权限、实验/主机/配置隔离、11 条跨用户越权攻击、WS 鉴权、CLI 全流程 —— 33/33 通过。

**原规划（设计对照）**

- **现状**：服务默认绑定 `127.0.0.1`，没有任何鉴权；所有实验、主机、配置共享一份本地数据。
- **问题 / 机会**：一旦要给别人用，或部署到可被局域网访问的机器，任何人都能看到并操作全部实验，甚至通过网页终端拿到服务器 shell。
- **建议做法**：
  - 引入最小可用账号体系（用户名 + 密码哈希，Flask-Login 或自建 session token）。
  - 数据层加 `user_id` 字段，主机 / 实验 / 运行按用户过滤；`config.json` 的 API Key 也按用户隔离。
  - 终端 WebSocket 握手时校验 session，未登录直接拒绝。
- **预期收益**：从"个人本地工具"跨过"可分享产品"的第一道门槛。
- **参考竞品**：OpenResearch 明确提示远程服务无应用层鉴权是已知短板——先把这点做对就是领先。

### 2. HTTPS 与终端安全　✅ 已完成（2026-11-18）

> **实现**：默认 `https://127.0.0.1:7788`，自签证书自动写在 `data/certs/`；HTTP 请求 308 跳转，Cookie 自动带 `Secure` / `HttpOnly`。网页在建立终端前先向 `POST /api/terminal/<hid>/ticket` 申请一次性票据，WebSocket 握手校验 Origin，空闲 15 分钟或总时长 4 小时自动断开。实验详情页提供 7 天有效的只读观察链接 `/observe/<token>`，终端也支持只读模式 `/terminal/<hid>/observe`。

- **现状**：原有网页终端通过 WebSocket 明文传输按键与输出，等价于一条实时 shell 通道。
- **问题 / 机会**：若将来通过反向代理或公网暴露，明文终端会被中间人窃取凭据、命令与结果。
- **已落地做法**：
  - 默认强制 HTTPS + WSS；本地自签证书自动生成，生产可替换正式证书。
  - 终端连接增加一次性 token、Origin 校验与超时自动断开。
  - 提供"只读观察模式"链接，供他人看实验但不给 shell。
- **预期收益**：把最敏感的入口（root 终端）保护起来，是能否被实验室 / 团队采用的硬条件。

### 3. 密钥与 API Key 加密存储　✅ 已完成（2026-11-18）

> **实现**：`core/crypto.py` 用 `data/secret.key`（或 `REKIT_MASTER_PASSWORD`）派生 Fernet 密钥，敏感字段以 `enc:v1:` 前缀加密落盘；启动时自动迁移旧明文。主机列表 API 不再返回密码/私钥路径，日志与 SSE 事件统一脱敏。`./rekit admin-password` 可查看解密后的 admin 初始密码。

- **现状**：SSH 密码、私钥路径、LLM API Key 集中在 `data/config.json`，但为明文。
- **问题 / 机会**：配置文件一旦泄露或被同步到云端，服务器与大模型的凭据全部暴露。
- **已落地做法**：
  - 字段级对称加密，配置里只存密文；需要时由主密钥解密到内存。
  - 日志与 SSE 事件中脱敏，禁止打印完整 Key。
  - 后续如需集中密钥管理，可把主密钥换成系统钥匙串引用，业务字段无需改动。
- **预期收益**：符合最基本的凭据安全规范，降低"用的人不敢填真实 Key"的阻力。

## P1 · 核心竞争力

### 4. git 原生实验谱系与可复现快照　✅ 已完成（2026-11-18）

> **实现**：`core/gitlineage.py` 把每个 `data/workspace/exp_<id>` 初始化为独立 git 仓库；每次运行前自动提交当前工作区并把 40 位 SHA 写入 `runs.git_sha`。实验页新增「Git 快照谱系」面板，支持查看任意 run 的 diff、恢复历史快照、从某次快照 fork 出新实验。只读观察页也展示每次运行对应的 commit。

- **现状**：原先每次运行只上传文件到服务器目录，改代码再跑会导致结果与代码版本漂移。
- **问题 / 机会**：科研最看重"这个数字到底是哪版代码跑出来的"。OpenResearch 正是把 git 原生实验树作为核心卖点。
- **已落地做法**：
  - 本地工作区初始化 git；每次 `run` 前自动 commit，记录 SHA 到 `runs.git_sha`。
  - 快照附带 `.rekit_snapshot.json`，锁定入口、运行命令与文件清单。
  - 实验页展示「Git 快照谱系」：Diff / 恢复 / Fork 三个操作。
  - Fork 会克隆源实验的 git 仓库并 checkout 到指定 commit 的 `fork-*` 分支，形成真实谱系。
- **预期收益**：结果可追溯、可复现，直接提升工具在严肃科研场景的可信度。
- **参考竞品**：OpenResearch（git-native experiment tree，每次 run 锁定 commit 快照）。

### 5. 结果核验模块（抑制 LLM 虚构结论）　✅ 已完成（2026-11-18）

> **实现**：`core/verify.py` 在总结生成时把报告文本里的数字逐条回查 `metrics` 表，未在指标中找到对应数值的标记为"待人工确认"；同时为每个指标生成"指标名 + step + 原始日志行号"的证据来源，并明确区分实测数据（`metrics_stats`）与推断性解读（`verdict` / `paper_paragraph`）。结论页新增「结果核验」面板，未验证数字、证据来源、判据判定与实测/推断说明一目了然；Markdown / Word / PDF 报告均附带核验章节。

- **现状**：自动总结由 LLM 结合日志尾部与指标统计生成；LLM 可能写出日志里并不存在的数字或过度解读。
- **问题 / 机会**：Google Co-Scientist 用"把文本里每个数值回查代码实际输出"的核验模块，把虚构关键结果比例从 46% 降到 4%。这是同类系统公认的核心风险。
- **建议做法**：
  - 强制总结引用指标时附来源（`metric 名 + step + 原始日志行号`），无来源的数字一律不写。
  - 增加一个规则校验层：抽取报告中的数值，逐条与 `metrics` 表比对，对不上的标记为待人工确认。
  - 报告里区分"实测结论"与"推测性解读"，后者明确标注。
- **预期收益**：显著降低幻觉结论，让报告敢于直接进论文草稿；与竞品的"可靠性模块"看齐。
- **参考竞品**：Google Co-Scientist（verification module）、Sakana AI Scientist（自动审稿 + evidence map）。

### 6. 人在环 checkpoint（copilot 模式）　✅ 已完成（2026-11-18）

> **实现**：实验页右上角可切换「自主 / 副驾驶」模式。副驾驶模式在方案、代码、运行三个阶段之间暂停，页面顶部出现醒目的"待确认"提示条，可填写批注（如"重点看消融""指标换成 AUROC"）后确认继续，批注会作为 feedback 回灌给下一阶段的 LLM 生成。所有模式切换与阶段确认都写入审计日志。

- **现状**：支持在阶段间手动修改方案与代码，但默认流程是一键跑到底。
- **问题 / 机会**：Agent Laboratory 的实验明确显示，人在每个阶段给反馈（copilot 模式）使论文评分从 3.8 提升到 4.38（满分 10）；纯自主反而更弱。
- **建议做法**：
  - 提供"自主 / 副驾驶"两档模式。副驾驶模式在方案、代码、总结三个节点暂停，等用户确认或批注再继续。
  - 批注作为上下文回灌给下一阶段（"数据集再小一点""重点看消融"）。
  - 前端用清晰的"待确认"状态与待办角标呈现。
- **预期收益**：把"人可介入"从口号变成有数据支撑的卖点，且更贴合科研者的掌控欲。
- **参考竞品**：Agent Laboratory（autonomous vs copilot）、Sakana Agentic Scientist（human co-discovery）。

## P1 · 科研可信度与规范性

### 7. 完整审计日志（防 p-hacking）　✅ 已完成（2026-11-18）

> **实现**：新增 `audit_log` 表，覆盖实验创建、方案生成/重做、代码生成/改动、判据保存与锁定、代码快照锁定、模式切换、创新点更换、总结生成等关键动作，记录动作、决策、参数摘要（改前/改后）与时间。实验页「实验过程 · 审计轨迹」以时间线呈现完整过程；报告导出自动附一段"实验过程摘要"。

- **现状**：events 表记录运行事件，但没有覆盖"谁改了代码 / 改了方案 / 改了判据"的完整操作轨迹。
- **问题 / 机会**：科研诚信要求"先定假设与判据，再看结果"。工具若不记录过程，很容易在无意中助长挑结果的行为。
- **建议做法**：
  - 所有实体（方案、代码、判据、指标定义）的每次修改都写不可变审计记录（谁、何时、改前改后）。
  - 实验档案页时间线展示完整过程，关键改动高亮。
  - 报告导出时附一段"实验过程摘要"。
- **预期收益**：把"可信"做成产品特性，可作为向导师 / 课题组推广的说服点。
- **参考竞品**：多数 MLOps 工具有 audit log，但少有与"假设—判据"绑定的科研语义。

### 8. 实验预注册与判据锁定　✅ 已完成（2026-11-18）

> **实现**：实验页「预注册判据」面板支持结构化判据（指标 / 运算符 / 阈值 / 取末值或最优）的可视化编辑与锁定。锁定后修改必须填写变更原因，旧判据与原因写入 `criteria_history_json` 并同步审计。总结生成时按锁定判据逐条自动判定（通过 / 未通过 / 待确认），并展示在结论与报告中。

- **现状**：方案里已有"成功 / 失败判据"字段，但跑完可以随意修改，缺乏"当初怎么定的"证据。
- **建议做法**：
  - 实验开始前允许"锁定判据"，锁定后修改需显式版本记录并说明原因。
  - 总结时对照"锁定判据 vs 最终结果"给出逐条判定。
- **预期收益**：从工具层面帮助用户养成良好的科研习惯，产出更经得起质疑的结论。

### 9. 随机种子、依赖与硬件环境固化　✅ 已完成（2026-11-18）

> **实现**：每次运行生成随机 seed 并通过 `SEED` 环境变量传入远程脚本，生成代码的 Prompt 强制要求读取该 seed 并设置 `random` / `numpy` / `torch` 随机种子。部署后自动采集 `pip freeze`、`nvidia-smi`、Python 版本、主机与采集时间，写入 `runs.env_json`，与代码快照 commit 一起作为"复现实验配置"展示在实验页与所有报告导出中。

- **现状**：装依赖与检测 GPU 已有，但种子、精确版本、硬件信息未随结果系统存档。
- **建议做法**：
  - 运行前自动写入 `seed`、requirements 精确版本、`nvidia-smi` 快照，随 run 一起存。
  - 报告里自动生成"复现实验配置"小节。
- **预期收益**：真正实现"照着报告能重跑出同样结果"。

## P2 · 体验与易用性

### 10. 报告导出 PDF / Word　✅ 已完成（2026-11-18）

> **实现**：`core/report.py` 汇总方案、结论、结果核验、判据判定、审计过程摘要与复现配置，输出完整 Markdown 与论文式 Word（三线表，含标题/假设/指标/论文段落等分节）。PDF 走浏览器打印页 `/report/<id>`，内置打印样式可直接"另存为 PDF"。三个导出入口都在结论区，支持从实验页与打印页跳转。

- **现状**：可导出 Markdown；CSS 已有 `@media print` 打印样式。
- **问题 / 机会**：实际投稿 / 汇报常要 PDF 或 Word，用户还要手工排版。
- **建议做法**：
  - PDF：用浏览器打印（现成打印样式）或服务端 WeasyPrint 生成。
  - Word：按论文式模板（标题 / 三线表 / 图）生成 `.docx`。
  - 支持选择导出范围（仅结论 / 结论+方案 / 全档案）。
- **预期收益**：把"报告可直接读写"的差异化做实，形成闭环交付。

### 11. 任务模板与批量 / 并行实验　✅ 已完成（2026-11-18）

> **实现**：内置训练分类器、LoRA 微调、超参网格、消融实验四个模板，首页选择模板即可填充创新点。批量面板支持 JSON 参数矩阵（如 `{"lr":[0.01,0.001],"bs":[32,64]}`）自动展开为最多 50 个独立实验，每个实验的方案里带上本次参数，可通过已有的多服务器列表分别排队运行。首页「批量实验对比」勾选多个实验即可按参数组合对照最新指标，并可一键"重试失败项"——只对失败/失联/停止且已有代码的实验重新入队，实现断点续跑。批量创建、参数组合与续跑都写入审计日志。

- **现状**：一次一个实验、一台服务器；没有超参扫描模板。
- **建议做法**：
  - 内置常见模板：训练分类器、LoRA 微调、超参网格、消融实验。
  - 支持一个方案生成多组参数、在多台服务器排队或并行执行，结果汇总到一张对比表。
  - 断点续跑：失败的任务只重跑失败项。
- **预期收益**：从"单实验工具"升级为"实验流水线"，显著提升重度用户价值。

### 12. 成本与用量统计　✅ 已完成（2026-11-18）

> **实现**：`core/llm.py` 记录每次 LLM 调用的 model、prompt/completion tokens 与 request id，`usage_log` 表按用户 / 实验 / 运行归档。实验页「成本用量」卡展示调用次数、总 token、输入/输出拆分与成本，并可设置 token 预算，超预算时显示告警；`/api/usage` 提供全局汇总。

- **建议做法**：记录每次方案的 LLM token 消耗、每次运行的 GPU 时长与失败重跑次数，做可视化账本与预算告警。
- **预期收益**：帮用户控制真实开销，也是团队采用的必要信息。

### 13. 交互细节　✅ 已完成（2026-11-18）

> **实现**：创新点区块的「换一份文稿」复用 `/api/extract` 抽取器并写回实验（带审计）；运行日志支持关键字搜索、全部/指标/错误/阶段类型筛选与连续重复行折叠；窄屏下布局自动堆叠为单列、按钮自适应；首页新增"最近运行"实时状态卡，最近 8 次运行中出现失败/失联/停止时顶部显示告警横幅。

- 实验详情页的"创新点"区块支持"换一份文稿"复用现有抽取器。
