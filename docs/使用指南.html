01

安装与启动

Quick Start

三步跑起来。默认绑定本机 127.0.0.1:7788 并启用 HTTPS，数据在 data/ 目录。

1. 安装依赖

bash
cd 科研实验助手
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt

2. 启动服务

bash
.venv/bin/python app.py
# 或者用启动器（服务没起会自动拉起）
./rekit server start
./rekit server          # 查看状态

3. 打开页面并登录

浏览器访问 https://127.0.0.1:7788。自签证书会提示不安全，点「继续访问」即可。首次启动自动创建管理员 admin，初始密码用下面的命令查看：

bash
./rekit admin-password
注意 / NOTE

网页终端等价于服务器 shell。默认只监听 127.0.0.1；若要给局域网他人使用，请先替换正式证书、做好网络隔离，不要把自签证书的实例直接暴露公网。

02

账号、注册与个人主页

Accounts

默认开启登录鉴权，实验、服务器、配置、文稿按账号隔离，互不可见。

  • 自助注册：登录页点「注册账号」创建成员账号；管理员可在「设置 → 账号管理」增删账号、改角色。
  • 双通道登录：浏览器用签名 Session Cookie；脚本 / CI 用 Bearer API Token（只存摘要，可随时轮换）。
  • 命令行登录：./rekit login -u admin -p 密码，令牌存到 data/cli_token（权限 600），之后命令免登录；也可用环境变量 REKIT_TOKEN 覆盖。
  • 网页端拿令牌：「设置 → 命令行登录令牌」生成，供多台机器或 CI 使用。
  • 个人主页：点顶部「个人主页」，上方是姓名 / 头像 / 完成度概览；名片、编辑资料、账号安全都收成缩略卡，点开后再查看或修改。
  • 编辑资料：在「编辑资料」卡里填姓名、单位、研究方向、技能、教育经历、邮箱与学术链接；资料按账号隔离保存。
  • 修改密码：展开「账号安全」卡，验证当前密码后修改。
提示 / TIP

命令行用 ./rekit whoami 确认当前登录身份；./rekit logout 删除本地令牌。忘记密码可让管理员在账号管理里重置。

项目 / 工作区与细粒度角色

  • 项目入口：顶部导航点「项目」，看到的是每个项目一个小卡片，显示角色、实验数和成员数；点卡片进入项目详情页，管理操作集中在「概览 / 成员 / 实验 / 分享」四个分区。
  • 项目设置：owner 可在「概览」里直接改名、改说明、归档或删除项目；删除项目不会删实验，实验会自动回到个人工作区。
  • 实验归组：owner 可在「实验」分区把实验移动到其他项目；首页创建实验时也能直接选所属项目。
  • owner：项目拥有者，可管理成员、归档项目、删除项目内实验、创建或撤销分享链接。
  • editor：可查看、改创新点/方案/代码/判据、生成分享链接、运行和停止实验，但不能删除实验，也不能管理成员。
  • viewer：只读角色，可看实验列表、指标、报告与日志，不能修改代码/判据、运行或分享。
  • 首页分组：实验按项目分组显示，创建实验时可先选「所属项目」，也可用项目筛选框快速切换。
  • 项目视图：项目页创建的分享链接打开后是只读项目视图，只展示实验列表与状态，不暴露代码、判据和运行日志。
提示 / TIP

老账号的历史实验会自动归入“某某的个人项目”，原有单人使用方式不变。要邀请他人协作，请在项目页用用户名添加成员并指定角色。

03

先配两样：大模型与服务器

Setup

正式建实验前，建议先把 LLM 和 SSH 主机配好并测试通过。不配 LLM 也能跑，但只会生成占位方案和占位代码（仅用于验证链路）。

3.1 配置大模型（设置页）

打开「设置」页，顶部是配置概览，所有设置项默认收起为缩略卡；点「配置 →」展开对应卡片即可修改。先展开「大模型」，填写任意 OpenAI 兼容接口，点「测试连通性」：

表 1　常见的兼容接口
服务接口地址（base_url）模型名示例
智谱https://open.bigmodel.cn/api/paas/v4glm-4-plus
DeepSeekhttps://api.deepseek.com/v1deepseek-chat
通义千问https://dashscope.aliyuncs.com/compatible-mode/v1qwen-max

填接口地址、模型名、API Key，按需调温度（默认 0.35），保存后测试。API Key 以 enc:v1: 加密落盘，界面只显示掩码。

提示 / TIP

方案和代码都靠模型生成，建议选能力较强的模型。该配置按用户隔离；管理员也可在 data/config.json 设系统默认值。

3.2 添加 SSH 服务器（服务器页）

打开「服务器 → 添加服务器」，逐项填写：

表 2　服务器字段说明
字段说明
名称易记的显示名，如「实验室 4090 机器」
主机地址 / 端口IP 或域名，端口默认 22
用户名如 root
认证方式密码（仅存本地数据库，加密）或私钥路径（如 ~/.ssh/id_rsa）
Python 解释器python3 或绝对路径 /opt/conda/bin/python
工作目录远程实验目录，默认 ~/research-runs
GPU勾选后每次监控会顺带采集 nvidia-smi

添加后务必点卡片上的「测试连接」确认能通。服务器卡片会显示本项目启动的任务及 step 进度，并通过 SSH ps 扫描手动运行的 Python 脚本（PID、命令、CPU/内存、运行时长）。

04

创建第一个实验

Create

首页现在是缩略卡片工作台：实验按项目分组显示成小卡片，最近运行也是紧凑卡片，创建面板默认收起，点「新建实验」再展开。批量对比、全局时间线和流程说明都放在折叠区，需要时再点开。创新点不用手打——支持拖拽或读取本地文稿。

4.1 写创新点

  • 直接在文本框写一段研究想法（至少 10 个字）。
  • 从文件读取：把 .md / .txt / .tex / .csv / .docx / .pdf 拖进输入框，或点「从文件读取」选择；读进来会自动填正文，标题空着时取文稿第一行。
  • PDF 解析需 pip install pypdf。

4.2 选模板（可选）

首页「实验模板」下拉可选：训练分类器、LoRA 微调、超参网格、消融实验。选中会填入对应创新点，可再改。在实验页「创新点」区块点「换一份文稿」也能随时替换，并自动记录审计。

4.3 批量参数实验（可选）

点「批量参数实验」展开面板，用 JSON 写参数矩阵，一次生成多个实验（最多 50 组）：

参数矩阵
{"lr":[0.01, 0.001], "batch_size":[32, 64]}

上例会生成 4 个实验（2×2），每组参数写进各自方案。创建后可在首页「批量实验对比」勾选多个实验，查看参数与最新指标的对比表；失败项可一键「重试失败项」实现断点续跑。

bash · 命令行创建
./rekit new -t "标题" -i @想法.md        # @ 开头读文件
./rekit auto -i @想法.docx              # 一条命令跑完全程
05

实验详情页全解

Experiment Page

详情页是主战场，七个区块默认收起为缩略卡，只显示一句摘要；点「查看 →」或点摘要卡展开完整内容，也可一键展开全部 / 收起全部。顶部按「生成/重做」「分享/管理」「运行」分组收拢操作，并提供可点击的流程导航；右侧监控栏集中展示阶段、指标、GPU 与日志。

表 3　实验详情页的七个区块
区块能做什么
① 创新点展开/收起原文；「换一份文稿」复用抽取器替换。
② 实验方案核心命题、可证伪假设、数据集、指标、基线、消融、成败判据与风险；「重新生成方案」可重做。
③ 代码可编辑的多文件实验代码；改动后点「保存」。遵循指标上报协议、自动检测 GPU、数据缺失时降级到合成数据。
④ 实验结论假设判定、关键发现、异常、局限、下一步与论文段落；下方是「结果核验」面板。
⑤ 预注册判据结构化判据编辑与锁定、变更记录、结果逐条判定。
⑥ 审计轨迹方案/代码/判据/运行/总结等全部关键操作的时间线。
⑦ 成本用量 · 复现配置LLM token 账本与预算；seed、Python、主机、代码 commit、pip freeze、nvidia-smi。

5.1 生成方案与代码

点顶部「重新生成方案」「重新生成代码」。生成是后台任务，进度会实时提示；带意见重做：在副驾驶模式的批注框里写，见第 7 节，或用命令行 ./rekit plan 3 -f "数据集再小一点"。

5.2 结果核验（抑制幻觉）

结论生成后自动运行核验：把报告里的数字逐条回查指标表，未找到来源的标为「待人工确认」；列出每个指标的证据来源（指标名 + step + 原始日志行号）；明确区分实测数据与推断性解读。图表中的「已核验 / 待人工确认」标记即来自这里。

诚信提醒 / NOTE

核验能显著降低虚构结论，但不能替代人工判断。写进论文前，请亲自复核关键数字与证据来源。

06

运行与实时监控

Run & Monitor

6.1 启动运行

  • 点顶部「运行实验」，选择一台服务器即开始部署：SFTP 上传 → 建 venv → 装依赖（失败自动切官方源重试）→ nohup 后台启动。
  • 长任务走「后台 + 退出码文件」轮询，SSH 断开也不会中断实验。
  • 运行前自动 git commit 当前代码，SHA 写入本次运行，结果可追溯到确切代码版本。
  • 运行前生成随机 seed 写入 SEED 环境变量，随 run 存档 seed / pip freeze / nvidia-smi。

6.2 看日志与曲线

右侧监控面板每 3 秒增量刷新：运行日志、指标曲线、GPU 状态、进程存活。日志工具条支持：

  • 搜索：按关键字过滤日志行；
  • 类型筛选：全部 / 仅指标 / 仅错误 / 仅阶段；
  • 折叠：把连续重复行折叠成「重复 ×N」；
  • ↓ 跳到最新，停止 发送停止信号。

日志卡住不增长会提醒；进程消失且没写退出码会判失败。服务重启后会自动接管正在跑的任务（按心跳与进程存活恢复，僵尸任务自动巡检处理），刷新页面也能补齐历史日志与指标。

6.3 指标上报协议

生成的代码会自动遵守；你自己写的代码按这个格式打印，一样能被监控和画图：

python
print("@@METRIC name=loss value=0.234 step=10", flush=True)
print("@@METRIC name=accuracy value=0.91 step=10", flush=True)

也识别常见的 loss: 0.23 / acc=0.9 写法做兜底。指标名建议用英文小写下划线，方便画曲线。

07

进阶功能

Advanced

这些功能让实验更可信、更可控，也是本工具相对同类产品的差异点。

副驾驶 checkpoint

右上角切「副驾驶模式」，方案 / 代码 / 运行各阶段会暂停等待确认，可写批注回灌给下一阶段。适合想要掌控每一步的场景。

预注册与判据锁定

在实验开始前锁定结构化判据（指标 + 运算符 + 阈值）；锁定后修改必须写原因并留历史。总结时按锁定判据逐条判定通过/未通过。

Git 快照谱系

每次运行锁定一个 commit。可查看任意 run 的代码 Diff、恢复历史快照、从某次快照 Fork 出新实验，形成真实谱系。

审计轨迹

谁在何时改了方案、代码、判据、创新点、模式，全部不可变记录。报告导出自动附一段实验过程摘要，防 p-hacking。

成本与用量

记录每次 LLM 调用的 token 与成本，在详情页看账本并设预算，超预算告警。/api/usage 提供全局汇总。

只读观察分享

详情页「只读观察」生成 7 天有效链接，他人能看实验与报告但拿不到终端 shell；终端也支持只读观察模式。

推送代码到 GitHub

配置加密 Token 后，把任意 run 的代码快照一键推到自己的仓库；报告里的 commit 变成可点击链接。

7.1 副驾驶模式怎么用

  1. 在实验页右上角点「自主模式」切到「副驾驶模式」。
  2. 页面顶部出现「待确认 · 方案阶段」提示条，写一句批注（如「重点看消融、指标换成 AUROC」）或直接确认。
  3. 确认后进入下一阶段，再次暂停于代码阶段、运行阶段；批注会作为 feedback 传给对应生成环节。
  4. 切回「自主模式」则取消暂停，一键跑到底。

7.2 判据锁定怎么用

  1. 在「预注册判据」区块点「编辑判据」，按行填：指标名、运算符（≥/>/≤/</==）、阈值、取末值或最优。
  2. 点「保存并锁定」。实验开始后再改会要求填写变更原因，旧判据与原因写入历史。
  3. 实验结束后，结论和报告里会按锁定判据逐条显示判定结果。

推送代码到 GitHub

GitHub Push

每次运行都会在本地锁定一个代码 commit。这个功能让你可以把任意一次 run 的快照推到自己的 GitHub 仓库，报告里的 commit 随之变成可点击链接——结果、代码版本、论文引用三者闭环。

第一步：在设置页配置仓库与 Token

  1. 到 GitHub → Settings → Developer settings → Personal access tokens → Fine-grained tokens，新建一个 Token，只授予目标仓库的 Contents: read and write（只读会推送失败报 403）。
  2. 打开本工具的「设置 → GitHub 集成」，填「仓库（owner/repo）」、Token 和默认分支（默认 main），点「测试连接」确认显示“可写”。
  3. 点「保存配置」。Token 用主密钥加密落盘、按账号隔离，页面只显示尾 4 位，明文不会回传前端。

第二步：在实验页推送

  1. 打开实验详情页的「Git 快照谱系」表格，找到想推送的 run（需先运行过一次，已有 commit）。
  2. 点该行「推送 GitHub」按钮，选择仓库（配置了多个时）并确认分支。
  3. 若代码里检测到疑似 API Key / 密码 / 内网地址，会弹出清单让你确认后才推送。
  4. 成功后该行出现「已推送 ↗」链接；导出 Markdown / Word / 打印报告，或在只读观察页，commit 都带上了 GitHub 链接。
安全提示 / SAFETY

建议用私有仓库起步，Token 只给单个仓库的最小权限；推送前务必确认代码里没有硬编码的数据路径、API Key 或服务器 IP。网络不通时推送会超时失败，可稍后重试，不会静默丢失。Token 一旦在别处泄露，请及时在 GitHub 上 Rotate。

语言与可访问性

Language & Accessibility

界面右上角有一个「文/A」按钮，点一下即可在中文和英文之间切换；选择会记在浏览器本地，下次打开保持。英文模式覆盖导航、标题、按钮、状态徽章、日志以及动态弹出的提示，新生成的表格内容也会自动翻译。

  • 切换语言：点右上角「文/A」，整页会刷新并切到另一种语言（切回中文时整页恢复为中文）。
  • 键盘操作：按 Tab 时先出现「跳到主要内容」链接；所有可点元素有清晰的焦点描边；弹窗按 Esc 可关闭。
  • 读屏友好：纯图标按钮带文字说明，通知会用 aria-live 播报，页面语言属性随中英文切换。
  • 看得清：所有文字与背景的对比度达到 WCAG AA 标准，长时间使用更省力。

统计、审稿与自动化

Statistics & Automation

这一组功能把「跑完一次」升级为「跑得可信、跑得省心」：多 run 统计让结论有数字支撑，AI 自审帮你找漏洞，失败诊断和 Webhook 通知让你不用一直守着页面。

  • 多 run 统计：同一实验运行多次后，实验页结论的「指标汇总」表会多出「多 run 均值±std」列；批量实验对比也带均值/样本数。两个实验做显著性比较可调用 /api/stats/compare（Welch t + Mann-Whitney U）。样本少于 5 次会提示谨慎解读。
  • AI 自审：结论生成后自动追加一轮「审稿人」调用，在结论区下方显示六维评分、主要/次要问题与待补实验；点「AI 自审」按钮可重新审。结果标注「AI 生成，需人工判断」。
  • AI 可信分级：实验页新增「AI 可信」卡片，把方案 / 代码 / 总结 / 审稿 / 诊断按「实测支持 / 日志代码支持 / AI 推断 / 外部知识 / 待验证」分级，并可展开逐句证据；报告导出也会附可信摘要。
  • AI 评测与工具沙箱：设置页可一键运行 5 个内置回归样例并查看历史通过率；「AI 工具沙箱」只允许白名单工具，写操作要二次确认，所有调用都留审计。
  • 失败诊断：实验失败时，日志区上方出现诊断卡——命中错误签名、给证据行号和修复建议（降 batch / 装依赖 / 改路径等）。
  • 分享与批注：实验页「分享设置…」可创建带密码、有效期、访问次数、脱敏的只读链接并可撤销；访客在观察页留的批注会汇总回实验页。
  • 搜索 / 标签 / 通知：首页可即时搜索实验、按状态筛选、看全局时间线；实验页可打标签、归档。设置页「通知告警」填 Webhook（企业微信/钉钉机器人）后，完成/失败/判据未通过会自动推送，可设免打扰时段。
  • 可靠性：LLM 调用遇 429/5xx/超时会自动重试、切换备用模型，连续失败熔断；SSH 连接复用、大文件上传支持断点续传。

10

常见问题排查

FAQ

按现象查找原因与处理办法。

浏览器提示证书不安全，页面打不开？

本地用的是自签证书，浏览器会告警，点「高级 → 继续访问」即可。若想消除告警，可购买/签发正式证书替换 data/certs/ 下的文件，并把域名加入 hosts。

测试连接失败 / SSH 连不上？

先确认主机地址、端口、用户名、密码或私钥正确；服务器需开启 SSH 密码认证或对应公钥。确认防火墙放行。网络可用时用 ./rekit host test 复测；凭据修改后需重新保存主机。若报认证失败，多半是密码/私钥不对，而不是服务问题。

点运行后一直停在「上传中 / 配置环境」？

看右侧日志尾部。常见原因：远程 Python 路径不对、pip 装依赖慢、磁盘空间不足。装依赖默认走清华镜像，失败会回退官方源。服务重启会自动接管还在跑的任务，不会一直卡住。

远程中文文件名显示成转义字符？

这是远端 LANG 为空导致的。网页终端连接时会探测并选择 UTF-8 locale 自动注入（sshd 不支持 AcceptEnv 时退回会话内 export），一般无需手动处理。

推送 GitHub 时报 403 / 没写权限？

Fine-grained Token 需要目标仓库的 Contents: read and write；只给只读会报“Write access ... not granted”。在 GitHub 上编辑 Token 权限后，回设置页重新保存即可。另外连不上 github.com:443 时会超时失败，稍后重试即可，不会静默丢失。

实验失败了，怎么排查？

打开实验页看监控面板的日志（可筛选「仅错误」）与退出码。常见：OOM（exit 137）、CUDA 显存不足、缺依赖、数据路径错误。修好后可重跑；批量实验用「重试失败项」只重跑失败组。代码有版本快照，可在 Git 谱系里恢复历史版本。

结论里有我不放心的数据怎么办？

看「结果核验」面板：标为「待人工确认」的数字在指标表里没有来源，请重点复核；每条实测值都能点开看证据来源（step 与日志行号）。核验只做机器检查，最终以你的人工判断为准。

忘了 admin 密码 / 命令提示未登录？

初始密码用 ./rekit admin-password 查看；若改过请以新密码为准。命令行未登录用 ./rekit login -u 用户名 -p 密码；网页直接用账号密码登录。令牌失效可 ./rekit token 重新生成。

数据会上传到云端吗？

不会。所有数据（数据库、密钥、文稿、代码、指标）都保存在本机 data/ 目录。只有访问 LLM 接口和连接你自己的 SSH 服务器时才会发出必要请求。凭据字段均加密落盘，日志与错误响应自动脱敏。

如何运行自测？

单元测试零依赖：python -m unittest discover -s tests -p 'test_*.py'（35 项，临时 data 目录隔离，不碰真实数据）。端到端测试需先起服务和 tests/fake_ssh_server.py，再跑 tests/e2e_test.py。
