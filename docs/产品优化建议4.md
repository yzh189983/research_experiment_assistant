## 产品定位：什么是卡卡智能体

「卡卡」不是一个通用聊天机器人，而是**绑定在科研实验助手里的项目级科研智能体**。

它应该具备四个特征：

1. **懂实验上下文**：知道当前项目、实验、方案、代码、判据、运行记录、指标和报告。
2. **能分阶段工作**：实验前生成脚本与计划，实验中盯日志与指标，实验后做总结与复盘。
3. **能进入协作场景**：在项目群聊中以成员身份播报进度、回答问题、分享结果。
4. **能主动找资料**：围绕研究任务检索论文、提取数据集、寻找官方链接与许可信息。

卡卡的输出必须继承现有 AI P0 规则：

- 五档可信分级：实测支持 / 日志代码支持 / AI 推断 / 外部知识 / 待验证
- 逐句证据绑定
- 项目角色权限继承
- 工具白名单与写操作二次确认
- 全量审计

## 52. 卡卡智能体：实验全生命周期副驾

- **优先级**：P0
- **一句话价值**：把“方案 → 代码 → 运行 → 监控 → 总结”从分散功能变成一个有状态、能解释、能接管各阶段的智能体。

### 现状

当前系统已经具备：

- AI 生成方案与代码
- SSH 部署与运行
- 实时监控日志 / 指标 / GPU
- 自动总结与 AI 自审
- 失败诊断与通知

但这些能力是“按钮驱动”的：用户需要在不同区块手动点生成、运行、总结。用户仍要自己判断下一步做什么。

### 问题 / 机会

用户真正想要的是：

> “我把研究想法告诉卡卡，它帮我把脚本写好；跑起来后它帮我盯着；跑完它直接告诉我结果怎么样、下一步该做什么。”

要把工具链升级为智能体，需要补上：

- 阶段状态机
- 上下文记忆
- 主动建议
- 人在环确认
- 统一对话入口

### 建议做法

#### 52.1 卡卡工作台

在实验页顶部新增一个固定入口：**「问卡卡 / 让卡卡继续」**。

卡卡面板包含：

- 当前阶段：想法 / 方案 / 代码 / 运行 / 总结 / 待人工确认
- 当前阻塞项：缺数据、缺依赖、判据未锁定、GPU 不足等
- 下一步建议：生成方案、生成代码、运行、补实验、重审
- 对话区：用户可以追问“为什么这么设计”“帮我换小一点的 batch”

#### 52.2 实验前：写实验脚本

卡卡根据创新点自动生成：

1. 研究假设
2. 实验方案
3. 数据需求
4. 指标与基线
5. 判据草稿
6. Python 实验脚本
7. 远程运行命令与依赖清单

用户可用两种方式确认：

- **自主模式**：卡卡一路生成到代码就绪，关键动作写审计
- **副驾驶模式**：每个阶段弹确认点，用户批注回灌给下一阶段

#### 52.3 实验中：监控运行状态

卡卡持续监听 SSE 事件与数据库状态：

- 日志是否停滞
- 指标是否异常波动
- GPU 是否长期空闲或打满
- 进程是否失败 / 失联 / 被 OOM kill
- 是否接近预算或超时

它不只显示数字，还要用自然语言说明：

```text
卡卡：run #12 已跑 8 分钟，loss 从 1.24 降到 0.61，
      但验证集 accuracy 连续 6 个 step 没增长。
      建议先不要停，再观察 2 分钟；若仍不增长，考虑降低学习率。
```

#### 52.4 实验后：总结实验结果

运行结束后卡卡自动完成：

- 聚合多 run 指标
- 生成结论草稿
- 执行数字核验
- 触发 AI 自审
- 判断判据通过 / 未通过
- 给出下一步实验建议
- 生成可导出的报告

总结必须带可信分级和证据绑定，不能只给漂亮话。

### 用户故事

- 作为研究者，我想把一句想法丢给卡卡，让它帮我把实验脚本写好。
- 作为研究者，我想在实验运行时让卡卡替我盯着异常，而不是一直刷日志。
- 作为研究者，我想跑完后直接拿到“结论 + 证据 + 下一步”，而不是自己拼报告。

### 验收口径

- 一个新实验能从创新点走到代码就绪，全程不超过 5 次人工确认。
- 实验异常能在 30 秒内出现在卡卡面板。
- 实验结束后自动产出总结、核验、自审和下一步建议。
- 每条卡卡结论可点开证据。

## 53. 项目群聊与智能体播报

- **优先级**：P1
- **一句话价值**：让项目组在同一个地方看实验进展、讨论结果，并让卡卡自动播报关键事件。

### 现状

当前项目协作方式：

- 项目成员与角色已经存在
- 全局时间线记录事件
- 通知通过 Webhook 推送到企业微信 / 钉钉
- 分享链接可以给访客只读查看

但项目内没有“讨论空间”。成员之间的沟通和实验系统是割裂的。

### 问题 / 机会

用户想要：

> “项目组的人拉个群，卡卡在群里发实验进度和实验结果，大家直接围绕结果讨论。”

群聊的价值在于：

- 上下文都在项目里，不必反复复制实验链接
- 卡卡可以主动播报，而不是人肉同步
- 成员可以 @卡卡 提问
- 新成员进群能快速看到最近发生了什么

### 建议做法

#### 53.1 项目群聊

每个项目自动拥有一个群聊空间：

- 入口：项目详情页 →「讨论」
- 成员：来自 `project_members`
- 角色：owner / editor / viewer 沿用项目角色
- 消息：文本、实验引用卡片、指标截图、文件附件
- 访客：分享链接默认不能进群，除非 owner 显式开启只读旁听

#### 53.2 卡卡作为群成员

卡卡在群里是一个特殊成员：

- 可被 @卡卡 提问
- 可主动播报事件
- 可发送实验卡片：标题、状态、最新指标、报告链接
- 可总结一段讨论：提取待办、结论和分歧
- 不会越权：viewer 问代码，卡卡只回复“无权限”

#### 53.3 自动播报事件

播报事件建议先支持：

- 实验创建
- 方案 / 代码生成完成
- 运行开始
- 运行失败
- 判据通过 / 未通过
- 总结生成
- 分享链接创建 / 撤销
- 成员加入 / 角色变更

播报要可配置，避免刷屏：

- 项目级开关
- 事件白名单
- 免打扰时段
-  Digest 模式：每小时 / 每天汇总一次

#### 53.4 群内问答

成员可以问：

```text
@卡卡 #12 为什么失败？
@卡卡 这个项目最近有没有判据未通过？
@卡卡 哪个实验 accuracy 最高？
@卡卡 把昨天的进展总结一下。
```

卡卡回答必须：

- 引用实验 ID / run ID / 报告段落
- 遵守项目角色
- 遵守脱敏规则
- 无法回答时明确说“证据不足”，不编造

### 用户故事

- 作为项目负责人，我想让卡卡自动把实验结果发到群里，省去人工同步。
- 作为项目成员，我想在群里 @卡卡 查某个实验为什么失败。
- 作为新成员，我想通过群聊快速了解项目最近进展。

### 验收口径

- 群成员完全继承项目角色，无权限用户无法进群或读到受限内容。
- 关键事件能在 10 秒内出现在群聊。
- 卡卡回答能点回实验 / run / 报告。
- 所有群内工具调用保留审计。

## 54. 数据集收集与链接发现智能体

- **优先级**：P1
- **一句话价值**：从相关论文里自动抽取“用了什么数据集、在哪里下载、有什么许可”，让实验准备阶段少做重复劳动。

### 现状

当前系统支持：

- 上传文稿 / PDF 抽取创新点
- 文献助理规划中（建议3 第 40 项）
- 项目可管理实验与资料

但用户仍要手动：

- 搜论文
- 找论文里用到的数据集
- 搜官方下载链接
- 核对数据集版本和许可
- 把数据集信息写进实验方案

### 问题 / 机会

用户想要：

> “给我一个研究方向，帮我把相关论文使用的数据集整理出来，并找到数据集链接。”

这个需求的难点不是“搜”，而是：

- 论文里的名字不统一（ImageNet / ILSVRC / ImageNet-1K）
- 数据集可能没有官方链接
- Hugging Face / GitHub / 官网 / DOI 都可能出现
- 许可协议与版本必须标明
- 不能把非官方镜像当成官方来源

### 建议做法

#### 54.1 输入

用户可以给三种输入：

1. 研究任务描述，例如“医学 VQA 幻觉检测”
2. 一组论文链接 / arXiv ID / DOI
3. 已上传的 PDF 文件夹

#### 54.2 论文检索

卡卡可检索：

- arXiv
- OpenAlex
- Crossref
- Semantic Scholar
- PubMed（医学方向）

每个来源要记录：

- 论文标题
- 作者
- 年份
- 链接
- 摘要
- 引用次数（如可得）
- 搜索关键词

#### 54.3 数据集抽取

从论文全文 / 摘要 / 实验章节中抽取：

- 数据集名称
- 数据集版本
- 训练 / 验证 / 测试划分
- 样本量
- 任务类型
- 使用方式
- 原文证据段落与页码

输出示例：

```json
{
  "dataset": "MIMIC-CXR",
  "version": "v2.0.0",
  "evidence": "We evaluated our method on MIMIC-CXR v2.0.0 ...",
  "page": 4,
  "split": {"train": 368960, "test": 5159}
}
```

#### 54.4 链接发现

对每个数据集尝试寻找：

- 官方网站
- Hugging Face Dataset
- GitHub 仓库
- DOI / Zenodo
- 论文补充材料
- 云盘 / 机构托管页

并标注：

- 官方 / 非官方
- 许可协议
- 访问日期
- 是否需要申请
- 是否需要登录

#### 54.5 数据集资产库

所有确认后的数据集进入项目资产库：

- 项目名称
- 数据集名称
- 版本
- 链接
- 许可证
- 用途
- 来源论文
- 证据引用
- 负责人
- 状态：候选 / 已确认 / 已下载 / 已用于实验

实验方案生成时，卡卡可以自动引用项目资产库中的数据集。

### 用户故事

- 作为研究者，我想输入一个研究方向，就得到相关论文常用数据集清单。
- 作为项目负责人，我想把团队用过的数据集统一管理，避免每个人重复找链接。
- 作为实验设计者，我想让卡卡在生成方案时优先使用项目里已确认的数据集。

### 验收口径

- 10 篇论文中能抽出主要数据集名称，且每条都有原文证据。
- 每条数据集链接标注来源类型与访问日期。
- 非官方链接不得标为官方。
- 许可信息不确定时标记“未知 / 需人工确认”。
- 数据集条目能一键进入方案草稿。

## 落地记录（2026-11-20）

三项需求均已完成首版实现，遵循 AI P0 的可信分级、证据绑定、角色继承与审计规则。

### 52 卡卡智能体

- 新增 `core/kaka.py`：`workspace()` 按想法 / 方案 / 代码 / 运行 / 总结 / 待确认六阶段判定，输出阻塞项与下一步；`ask()` 基于实验上下文回答，证据不足时明确说「证据不足」；`prepare_script()` 校验写权限并复用现有方案 / 代码生成任务；`summarize_result()` 复用总结器并绑定证据、登记可信输出。
- 实验详情页顶部新增「卡卡工作台」卡片，阶段、监控小结、阻塞项与下一步可一键操作；SSE 状态 / 总结事件会实时刷新工作台。
- 右下角新增全局卡卡形象：纯 CSS 绘制的眨眼 / 浮动 / 点头动画，眼睛跟随鼠标；点击弹出右侧聊天栏，支持带历史的多轮对话，按 global / exp:<id> / project:<id> 分开保存到 `kaka_conversations` 与 `kaka_messages`，可一键清空。实验页工作台的「问卡卡…」也会打开这个聊天栏。

### 53 项目群聊与智能体播报

- 新增 `project_messages` 表与 `add_project_message()` / `list_project_messages()`；项目详情页新增「讨论」页，owner / editor 可发言与 @卡卡 提问，viewer 只读。
- `kaka.broadcast()` 限定事件白名单（运行完成 / 失败、总结生成等），`core/monitor.py::_finish()` 在关键节点自动播报；成员与发言权限继承项目角色，分享观察页不暴露群聊。

### 54 数据集收集与链接发现

- 新增 `project_datasets` 表与增删改查函数；项目详情页新增「数据集」页，支持研究方向匹配、勾选收录、状态标记与删除。
- `kaka.collect_datasets()` 先经 `core/dataset_search.py` 联网检索 OpenAlex / arXiv 论文，从摘要提取数据集（模型优先、目录兜底），再到 Hugging Face / Zenodo 与内置官方目录补全链接与许可；前端展示来源论文，不确定项标「未知 / 需人工确认」。设置页「外部检索」卡片可开关与调来源，失败自动降级不影响收集。
- 删除项目 / 用户时同步清理群聊与数据集数据。

### 验证

- 新增 `tests/test_kaka.py` 五项测试（工作台阶段、证据不足回答、播报白名单、数据集收集与收录、无角色拒绝）。
- 完整测试套件 54 项全部通过。

### 首版边界

- 已接入 OpenAlex / arXiv 论文检索与 Hugging Face / Zenodo 链接发现；论文按内置名单优先 CCF-A / 中科院一区并标注级别，数据集尽量给出文件级下载链接（优先 parquet / zip / csv 等数据文件）。刊物级别按内置名单匹配、以官方名单为准；仍不做论文全文下载与页码级证据定位。支持按起始 / 结束年份限定论文范围（设置页配默认值，搜索框可临时覆盖）。可在「设置 → 外部检索」调整偏好与来源。
- 群聊播报为事件触发，Digest 汇总与免打扰时段沿用通知模块的现有配置，未单独做项目级开关。
- 卡卡问答与数据集抽取默认由大模型驱动，可在设置页单独配模型（留空跟随主模型）；模型不可用或未配置时退回内置规则。复杂问题会明确回复「证据不足」，不编造结论。

## 共同依赖与边界

### 共同依赖

1. **项目与角色体系**：三项需求都依赖项目 / owner / editor / viewer。
2. **AI 可信底座**：卡卡输出必须带可信分级和证据。
3. **工具沙箱**：检索论文、查实验、读指标都走白名单工具。
4. **事件系统**：群聊播报依赖现有 SSE / audit / stream_events。
5. **LLM 可靠性**：卡卡会频繁调用模型，必须沿用重试、fallback、熔断与成本账本。
6. **报告系统**：实验总结与群聊结果都要能点回报告。

### 明确不做

- 不把卡卡做成通用聊天机器人。
- 不让卡卡绕过项目角色读取实验。
- 不让卡卡自动覆盖实验代码或报告。
- 不把未经核实的数据集链接标为官方来源。
- 不在分享观察页里暴露项目群聊。
- 不把 AI 推断写成实测结论。
