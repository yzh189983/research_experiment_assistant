## 产品定位：什么是卡卡智能体

「卡卡」不是一个通用聊天机器人，而是**绑定在科研实验助手里的项目级科研智能体**。

它应该具备四个特征：

1. **懂实验上下文**：知道当前项目、实验、方案、代码、判据、运行记录、指标和报告。
2. **能分阶段工作**：实验前生成脚本与计划，实验中盯日志与指标，实验后做总结与复盘。
3. **能进入协作场景**：在项目群聊中以成员身份播报进度、回答问题、分享结果。
4. **能主动找资料**：围绕研究任务检索论文、提取数据集、寻找官方链接与许可信息。

卡卡的输出必须继承现有 AI P0 规则：

- 五档可信分级：实测支持 / 日志代码支持 / AI 推断 / 外部知识 / 待验证
- 逐句证据绑定
- 项目角色权限继承
- 工具白名单与写操作二次确认
- 全量审计

## 52. 卡卡智能体：实验全生命周期副驾

- **状态**：✅ 已完成首版（2026-11-20），见《落地记录》
- **优先级**：P0
- **一句话价值**：把“方案 → 代码 → 运行 → 监控 → 总结”从分散功能变成一个有状态、能解释、能接管各阶段的智能体。
- **完成范围**：52.1 工作台 ✅　52.2 实验前写脚本 ✅　52.3 实验中监控 ✅　52.4 实验后总结 ✅

### 现状

当前系统已经具备：

- AI 生成方案与代码
- SSH 部署与运行
- 实时监控日志 / 指标 / GPU
- 自动总结与 AI 自审
- 失败诊断与通知

但这些能力是“按钮驱动”的：用户需要在不同区块手动点生成、运行、总结。用户仍要自己判断下一步做什么。

### 问题 / 机会

用户真正想要的是：

> “我把研究想法告诉卡卡，它帮我把脚本写好；跑起来后它帮我盯着；跑完它直接告诉我结果怎么样、下一步该做什么。”

要把工具链升级为智能体，需要补上：

- 阶段状态机
- 上下文记忆
- 主动建议
- 人在环确认
- 统一对话入口

### 建议做法

#### 52.1 卡卡工作台

在实验页顶部新增一个固定入口：**「问卡卡 / 让卡卡继续」**。

卡卡面板包含：

- 当前阶段：想法 / 方案 / 代码 / 运行 / 总结 / 待人工确认
- 当前阻塞项：缺数据、缺依赖、判据未锁定、GPU 不足等
- 下一步建议：生成方案、生成代码、运行、补实验、重审
- 对话区：用户可以追问“为什么这么设计”“帮我换小一点的 batch”

#### 52.2 实验前：写实验脚本

卡卡根据创新点自动生成：

1. 研究假设
2. 实验方案
3. 数据需求
4. 指标与基线
5. 判据草稿
6. Python 实验脚本
7. 远程运行命令与依赖清单

用户可用两种方式确认：

- **自主模式**：卡卡一路生成到代码就绪，关键动作写审计
- **副驾驶模式**：每个阶段弹确认点，用户批注回灌给下一阶段

#### 52.3 实验中：监控运行状态

卡卡持续监听 SSE 事件与数据库状态：

- 日志是否停滞
- 指标是否异常波动
- GPU 是否长期空闲或打满
- 进程是否失败 / 失联 / 被 OOM kill
- 是否接近预算或超时

它不只显示数字，还要用自然语言说明：

```text
卡卡：run #12 已跑 8 分钟，loss 从 1.24 降到 0.61，
      但验证集 accuracy 连续 6 个 step 没增长。
      建议先不要停，再观察 2 分钟；若仍不增长，考虑降低学习率。
```

#### 52.4 实验后：总结实验结果

运行结束后卡卡自动完成：

- 聚合多 run 指标
- 生成结论草稿
- 执行数字核验
- 触发 AI 自审
- 判断判据通过 / 未通过
- 给出下一步实验建议
- 生成可导出的报告

总结必须带可信分级和证据绑定，不能只给漂亮话。

### 用户故事

- 作为研究者，我想把一句想法丢给卡卡，让它帮我把实验脚本写好。
- 作为研究者，我想在实验运行时让卡卡替我盯着异常，而不是一直刷日志。
- 作为研究者，我想跑完后直接拿到“结论 + 证据 + 下一步”，而不是自己拼报告。

### 验收口径

- 一个新实验能从创新点走到代码就绪，全程不超过 5 次人工确认。
- 实验异常能在 30 秒内出现在卡卡面板。
- 实验结束后自动产出总结、核验、自审和下一步建议。
- 每条卡卡结论可点开证据。

## 53. 项目群聊与智能体播报

- **状态**：✅ 已完成首版（2026-11-20），见《落地记录》
- **优先级**：P1
- **一句话价值**：让项目组在同一个地方看实验进展、讨论结果，并让卡卡自动播报关键事件。
- **完成范围**：53.1 项目群聊 ✅　53.2 卡卡作为群成员 ✅　53.3 自动播报 ✅（Digest / 免打扰沿用通知模块）　53.4 群内问答 ✅　补充：输入 `@` 自动弹出可提及对象 ✅（2026-11-21）

### 现状

当前项目协作方式：

- 项目成员与角色已经存在
- 全局时间线记录事件
- 通知通过 Webhook 推送到企业微信 / 钉钉
- 分享链接可以给访客只读查看

但项目内没有“讨论空间”。成员之间的沟通和实验系统是割裂的。

### 问题 / 机会

用户想要：

> “项目组的人拉个群，卡卡在群里发实验进度和实验结果，大家直接围绕结果讨论。”

群聊的价值在于：

- 上下文都在项目里，不必反复复制实验链接
- 卡卡可以主动播报，而不是人肉同步
- 成员可以 @卡卡 提问
- 新成员进群能快速看到最近发生了什么

### 建议做法

#### 53.1 项目群聊

每个项目自动拥有一个群聊空间：

- 入口：项目详情页 →「讨论」
- 成员：来自 `project_members`
- 角色：owner / editor / viewer 沿用项目角色
- 消息：文本、实验引用卡片、指标截图、文件附件
- 访客：分享链接默认不能进群，除非 owner 显式开启只读旁听

#### 53.2 卡卡作为群成员

卡卡在群里是一个特殊成员：

- 可被 @卡卡 提问
- 可主动播报事件
- 可发送实验卡片：标题、状态、最新指标、报告链接
- 可总结一段讨论：提取待办、结论和分歧
- 不会越权：viewer 问代码，卡卡只回复“无权限”

#### 53.3 自动播报事件

播报事件建议先支持：

- 实验创建
- 方案 / 代码生成完成
- 运行开始
- 运行失败
- 判据通过 / 未通过
- 总结生成
- 分享链接创建 / 撤销
- 成员加入 / 角色变更

播报要可配置，避免刷屏：

- 项目级开关
- 事件白名单
- 免打扰时段
-  Digest 模式：每小时 / 每天汇总一次

#### 53.4 群内问答

成员可以问：

```text
@卡卡 #12 为什么失败？
@卡卡 这个项目最近有没有判据未通过？
@卡卡 哪个实验 accuracy 最高？
@卡卡 把昨天的进展总结一下。
```

卡卡回答必须：

- 引用实验 ID / run ID / 报告段落
- 遵守项目角色
- 遵守脱敏规则
- 无法回答时明确说“证据不足”，不编造

### 用户故事

- 作为项目负责人，我想让卡卡自动把实验结果发到群里，省去人工同步。
- 作为项目成员，我想在群里 @卡卡 查某个实验为什么失败。
- 作为新成员，我想通过群聊快速了解项目最近进展。

### 验收口径

- 群成员完全继承项目角色，无权限用户无法进群或读到受限内容。
- 关键事件能在 10 秒内出现在群聊。
- 卡卡回答能点回实验 / run / 报告。
- 所有群内工具调用保留审计。

## 54. 数据集收集与链接发现智能体

- **状态**：✅ 已完成首版（2026-11-20），见《落地记录》
- **优先级**：P1
- **一句话价值**：从相关论文里自动抽取“用了什么数据集、在哪里下载、有什么许可”，让实验准备阶段少做重复劳动。
- **完成范围**：54.1 输入 ✅（研究任务描述）　54.2 论文检索 ✅（OpenAlex / arXiv）　54.3 数据集抽取 ✅（摘要提取）　54.4 链接发现 ✅（HF / Zenodo + 内置目录）　54.5 资产库 ✅；补充：CCF-A / 中科院一区优先、年份范围、文件级下载链接 ✅（2026-11-20）

### 现状

当前系统支持：

- 上传文稿 / PDF 抽取创新点
- 文献助理规划中（建议3 第 40 项）
- 项目可管理实验与资料

但用户仍要手动：

- 搜论文
- 找论文里用到的数据集
- 搜官方下载链接
- 核对数据集版本和许可
- 把数据集信息写进实验方案

### 问题 / 机会

用户想要：

> “给我一个研究方向，帮我把相关论文使用的数据集整理出来，并找到数据集链接。”

这个需求的难点不是“搜”，而是：

- 论文里的名字不统一（ImageNet / ILSVRC / ImageNet-1K）
- 数据集可能没有官方链接
- Hugging Face / GitHub / 官网 / DOI 都可能出现
- 许可协议与版本必须标明
- 不能把非官方镜像当成官方来源

### 建议做法

#### 54.1 输入

用户可以给三种输入：

1. 研究任务描述，例如“医学 VQA 幻觉检测”
2. 一组论文链接 / arXiv ID / DOI
3. 已上传的 PDF 文件夹

#### 54.2 论文检索

卡卡可检索：

- arXiv
- OpenAlex
- Crossref
- Semantic Scholar
- PubMed（医学方向）

每个来源要记录：

- 论文标题
- 作者
- 年份
- 链接
- 摘要
- 引用次数（如可得）
- 搜索关键词

#### 54.3 数据集抽取

从论文全文 / 摘要 / 实验章节中抽取：

- 数据集名称
- 数据集版本
- 训练 / 验证 / 测试划分
- 样本量
- 任务类型
- 使用方式
- 原文证据段落与页码

输出示例：

```json
{
  "dataset": "MIMIC-CXR",
  "version": "v2.0.0",
  "evidence": "We evaluated our method on MIMIC-CXR v2.0.0 ...",
  "page": 4,
  "split": {"train": 368960, "test": 5159}
}
```

#### 54.4 链接发现

对每个数据集尝试寻找：

- 官方网站
- Hugging Face Dataset
- GitHub 仓库
- DOI / Zenodo
- 论文补充材料
- 云盘 / 机构托管页

并标注：

- 官方 / 非官方
- 许可协议
- 访问日期
- 是否需要申请
- 是否需要登录

#### 54.5 数据集资产库

所有确认后的数据集进入项目资产库：

- 项目名称
- 数据集名称
- 版本
- 链接
- 许可证
- 用途
- 来源论文
- 证据引用
- 负责人
- 状态：候选 / 已确认 / 已下载 / 已用于实验

实验方案生成时，卡卡可以自动引用项目资产库中的数据集。

### 用户故事

- 作为研究者，我想输入一个研究方向，就得到相关论文常用数据集清单。
- 作为项目负责人，我想把团队用过的数据集统一管理，避免每个人重复找链接。
- 作为实验设计者，我想让卡卡在生成方案时优先使用项目里已确认的数据集。

### 验收口径

- 10 篇论文中能抽出主要数据集名称，且每条都有原文证据。
- 每条数据集链接标注来源类型与访问日期。
- 非官方链接不得标为官方。
- 许可信息不确定时标记“未知 / 需人工确认”。
- 数据集条目能一键进入方案草稿。

## 55. 卡卡技能配置

- **状态**：✅ 已完成首版（2026-11-21），见《落地记录》
- **优先级**：P1
- **一句话价值**：让卡卡从“固定能力”变成“可装配能力”，用户按研究方向给它装技能、调参数、定触发条件。
- **完成范围**：55.1 技能定义 ✅　55.2 设置页技能市场 ✅（含 ClawHub 搜索 / 导入）　55.3 可信边界 ✅　55.4 场景组合 ⬜（场景预设 / 阶段绑定尚未实现）；补充：对话内按次选择技能 ✅（2026-11-21）

### 现状

当前卡卡的能力写在代码里：写方案 / 写脚本 / 盯监控 / 总结 / 问答 / 找数据集。模型可以在设置页单独配置，但**能力本身不可插拔、不可扩展、不可按场景开关**。

### 问题 / 机会

不同研究者需要的技能不同：

> “我做医学影像，希望卡卡默认会看 DICOM 和 AUC；我做 NLP，只想让它管 BLEU / 困惑度，不想看到 GPU 告警刷屏。”

需要一个技能层，把卡卡的每项能力变成可声明、可配置的单元。

### 建议做法

#### 55.1 技能定义

每个技能是一个带 schema 的声明（内置技能随产品分发，用户技能可导入）：

```yaml
skill: metric_watch
name: 指标异常监测
triggers: [run.running, metric.updated]
params:
  patience: 6          # 连续 N 步不增长才提示
  improve_threshold: 0.01
requires: [metrics.read, log.read]
tier: verified
enabled: true
```

字段建议包含：唯一名、显示名、触发事件、参数、所需权限、可信档位、开关。

#### 55.2 技能配置界面

设置页新增「卡卡技能」卡片：

- 技能列表：内置 / 自定义分组，开关启用
- 参数编辑：按 schema 渲染表单，带默认值与说明
- 权限核对：所需权限超出卡卡当前角色时禁用并提示
- 导入 / 导出：技能配置可随项目或账号备份

#### 55.3 技能与可信底座

- 技能调用仍走白名单工具与写操作二次确认
- 每个技能输出绑定可信档位与证据
- 技能的所有调用写入审计，可追溯到具体参数

#### 55.4 技能组合与场景

- 场景预设：如“医学影像”“NLP 评估”“小样本”，一键切换一组技能
- 阶段绑定：某技能只在实验前 / 中 / 后启用
- 冲突提示：两个技能同时写同一资源时提示用户选择

### 用户故事

- 作为研究者，我想只为卡卡开启我需要的技能，减少无关提醒。
- 作为高级用户，我想调“异常监测”的耐心阈值，让它更灵敏或更迟钝。
- 作为团队成员，我想把一套技能配置导出给同事复用。

### 验收口径

- 至少 5 个内置技能可开关与配参。
- 技能输出遵守可信分级与证据绑定。
- 禁用技能后不再触发对应行为与播报。
- 技能配置可导出 / 导入，权限越界被拦截。

## 56. RSI 自进化

- **状态**：✅ 已完成首版（2026-11-21），见《落地记录》
- **优先级**：P2
- **一句话价值**：让卡卡从“按固定提示词工作”升级为“用历史经验改进自己的工作方式”，且全程可审计、可回滚。
- **完成范围**：56.1 经验采集 ✅　56.2 改进提案 ✅（含正面反馈保留风格提案）　56.3 人在环确认 ✅　56.4 安全边界 ✅；默认关闭、须人工批准、可回滚。

> RSI = Recursive Self-Improvement（递归自我改进）。本功能是**受限、人在环**的自进化：卡卡只能改进提示词模板、技能参数与检索策略，不能自行修改代码、判据或报告结论。

### 现状

卡卡的提示词与规则写在 `core/kaka.py` 的常量里，每次行为一致。历史上哪些建议被采纳、哪些被忽略、哪些结论被人工纠正，没有被系统性回流。

### 问题 / 机会

> “卡卡第三次把 loss 抖动误判成训练失败，我希望它能从我的纠正里学会，下次别再犯。”

需要一条闭环：记录行为 → 收集反馈 → 提炼改进 → 人工确认 → 生效 → 观测效果。

### 建议做法

#### 56.1 经验采集

记录卡卡每次关键行为的上下文与结果：

- 行为类型：建议、告警、结论、检索词
- 上下文快照：阶段、指标、判据、对话摘要
- 反馈信号：用户采纳 / 忽略 / 纠正 / 打分
- 结果标注：事后是否被证明正确

#### 56.2 改进提案

卡卡定期（如每周）离线分析经验，生成改进提案：

- 提示词措辞调整（如“抖动”判定更保守）
- 技能参数建议（如提高 patience）
- 检索策略优化（如优先某来源）
- 不直接改代码，只产出**提案文件**

#### 56.3 人在环确认

- 提案进入「卡卡自进化」审核队列，逐条展示“旧行为 → 新行为 → 依据案例”
- 用户批准后才生效，可单条回滚
- 所有版本留痕，形成提示词 / 参数的变更历史

#### 56.4 安全边界

- 禁止自改代码、实验脚本、判据、报告结论
- 禁止绕过项目角色与工具白名单
- 改进只在用户批准范围生效，默认关闭 RSI
- 每次进化后可对比前后指标（误报率、采纳率）

### 用户故事

- 作为研究者，我想让卡卡从我的纠正里逐步改进，而不是每次都重复同样的误判。
- 作为负责人，我想审核每一次“进化”，确认合理才让它生效。
- 作为审计者，我想看到卡卡行为规则随时间的所有变更与依据。

### 验收口径

- 经验采集覆盖建议 / 告警 / 结论三类行为。
- 改进提案可逐条审核、批准、回滚，默认关闭。
- 进化不改变 AI P0 的可信与权限约束。
- 有前后对比指标证明改进有效，否则不自动生效。

## 57. 上下文可视化

- **状态**：✅ 已完成首版（2026-11-21），见《落地记录》
- **优先级**：P1
- **一句话价值**：把卡卡“眼前看到的世界”画出来，让用户知道它凭什么这么说，并能直接修正它的视野。
- **完成范围**：57.1 上下文面板 ✅（「看依据」）　57.2 可视化呈现 ✅（来源分区 + 证据列表）　57.4 可信联动 ✅；57.3 可编辑上下文 ⬜（勾选 / 临时注入 / 对比重问尚未实现）。补充：模型上下文用量可视化 ✅（2026-11-21，`15K / 128K` 进度条）。

### 现状

卡卡回答时会在后台拼装上下文——实验信息、最近指标、日志尾行、阶段、项目群聊摘要。用户看不到这些，只能看到结论，难以判断它是否有足够依据。

### 问题 / 机会

> “卡卡说 accuracy 最高，我想知道它到底看了哪些 run、哪个时间窗、有没有漏掉我刚补的那次实验。”

把上下文显式化，既能建立信任，也能让用户纠正卡卡的视野。

### 建议做法

#### 57.1 上下文面板

每次卡卡回答旁提供「查看本次上下文」：

- 实验卡片：标题、状态、方案摘要、判据
- 指标窗口：读取了哪些指标、时间范围、数值点
- 日志证据：命中的原始日志行（带行号）
- 对话记忆：引用的最近 N 轮历史
- 项目信息：群聊摘要、成员、关联实验

#### 57.2 可视化呈现

- 时间轴：实验事件与指标点对齐
- 证据高亮：回答中的数字点击跳到对应指标 / 日志行
- 上下文来源标签：实测 / 日志 / 推断 / 外部知识分色
- 缺失提示：某结论缺少支撑时标“证据不足”

#### 57.3 可编辑上下文

- 用户可勾选“本次回答包含 / 排除哪些上下文”
- 可手动补充一段背景（临时注入，不污染永久记忆）
- 调整后重新提问，对比两次回答差异

#### 57.4 与可信分级联动

- 上下文面板与现有五档可信分级共用证据源
- 每条 AI 输出可展开“它看了什么 → 它说了什么”
- 上下文快照随审计记录持久化，可回放

### 用户故事

- 作为研究者，我想看到卡卡回答时依据的指标和日志，确认它没漏数据。
- 作为审稿人，我想点结论里的数字直接跳到原始证据。
- 作为用户，我想临时补充背景让卡卡重新回答，而不改我的实验记录。

### 验收口径

- 每次卡卡回答都能展开完整上下文来源。
- 回答中的关键数字可点击跳到证据。
- 上下文调整后重新提问生效，且不污染原始数据。
- 上下文快照随审计持久化，可回放。

## 58. SuperAgent：会话管理与话题路由

- **状态**：✅ 已完成首版（2026-11-21），见《落地记录》
- **优先级**：P1
- **一句话价值**：用一个“超级会话入口”管理最近一周的对话，按话题自动归并或新建，避免同一个问题散落在多个会话里。
- **完成范围**：58.1 最近一周会话列表 ✅（左侧独立侧边栏）　58.2 话题识别与路由 ✅　58.3 会话数据结构升级 ✅　58.4 权限与边界 ✅　58.5 与技能 / 上下文联动 ✅；补充：全局直问 + 会话内询问双模式 ✅、会话垃圾箱（移入 / 恢复 / 彻底删除）✅（2026-11-21）。

### 现状

当前卡卡对话按 scope 固定分为 `global` / `exp:<id>` / `project:<id>`，存于 `kaka_conversations` 与 `kaka_messages`。

- 每种 scope 只有一个会话，历史不断追加，久了混杂多个话题
- 用户想找回“上周讨论 batch size 的那段对话”只能从头翻
- 同一个话题可能在全局、实验、项目里各聊一遍

### 问题 / 机会

> “我想要一个统一入口：最近一周我聊过哪些话题，点进去接着聊；如果我又问同一个话题，就续上旧会话；如果是新话题，就自动开一个新会话。”

### 建议做法

#### 58.1 最近一周会话列表

SuperAgent 入口展示最近 7 天的会话：

- 按话题分组，每条显示话题标题、最后更新时间、关联实验 / 项目
- 支持按实验、项目、关键词筛选（筛选界面尚未实现）
- 过时话题可移入垃圾箱，可恢复或彻底删除；置顶尚未实现

#### 58.2 话题识别与路由

新消息到来时自动判断归属：

1. 提取话题关键词（轻量中英文切词 + 停用词过滤，未使用向量表示）
2. 与最近一周会话话题比对，计算关键词交集相似度
3. 超过阈值（默认 0.4）→ 接续到最相近会话，保留上下文
4. 低于阈值 → 新建会话，自动生成话题标题
5. 阈值与“一周窗口”（默认 7 天）为内置默认值，暂未在界面开放配置

#### 58.3 会话数据结构升级

在现有表基础上扩展：

- `kaka_conversations` 增加：`topic`、`keywords`、`last_active_at`、`status`（active / archived / trash）
- 消息携带 `topic_hint` 与 `context_json`，便于后续重路由与回查
- 保留 scope 字段以兼容现有权限隔离，话题路由不得跨用户或越权项目

#### 58.4 权限与边界

- 话题路由只在用户有权访问的 scope 内进行
- 不把项目 A 的话题续到项目 B（避免越权泄漏）
- 用户可手动指定会话或强制新建，覆盖自动判断
- 路由决策写入审计，可解释“为什么续到这个会话”

#### 58.5 与技能 / 上下文联动

- 接续旧会话时，附带该话题的历史上下文摘要
- 不同话题的新会话可自动装配不同技能组合（呼应 55）
- 上下文面板（57）展示话题路由依据

### 用户故事

- 作为研究者，我想在统一入口看到最近一周聊过的话题并接着聊。
- 作为用户，我想重复问同一话题时自动续上，不必从头交代背景。
- 作为负责人，我想确保话题归并不会把不同项目的内容混在一起。

### 验收口径

- 最近一周会话按话题展示；筛选 / 置顶尚未实现，归档改为垃圾箱（移入 / 恢复 / 彻底删除）。
- 相同话题续接、不同话题新建的判定准确率可评测（给出测试集）。
- 话题路由不跨用户、不跨无权限项目。
- 用户可手动覆盖自动路由，决策可解释、可审计。

- 已接入 OpenAlex / arXiv 论文检索与 Hugging Face / Zenodo 链接发现；论文按内置名单优先 CCF-A / 中科院一区并标注级别，数据集尽量给出文件级下载链接（优先 parquet / zip / csv 等数据文件）。刊物级别按内置名单匹配、以官方名单为准；仍不做论文全文下载与页码级证据定位。支持按起始 / 结束年份限定论文范围（设置页配默认值，搜索框可临时覆盖）。可在「设置 → 外部检索」调整偏好与来源。

## 共同依赖与边界

### 共同依赖

1. **项目与角色体系**：全部需求都依赖项目 / owner / editor / viewer，话题路由（58）不得跨无权限项目。
2. **AI 可信底座**：卡卡输出必须带可信分级和证据；上下文可视化（57）与之共用证据源。
3. **工具沙箱**：检索论文、查实验、读指标都走白名单工具；技能配置（55）与 RSI（56）不得绕过。
4. **事件系统**：群聊播报依赖现有 SSE / audit / stream_events；技能触发（55）复用同一事件总线。
5. **LLM 可靠性**：卡卡会频繁调用模型，必须沿用重试、fallback、熔断与成本账本。
6. **报告系统**：实验总结与群聊结果都要能点回报告。
7. **会话存储**：SuperAgent（58）在 `kaka_conversations` / `kaka_messages` 上扩展，需兼容现有 scope 隔离。

### 明确不做

- 不把卡卡做成通用聊天机器人。
- 不让卡卡绕过项目角色读取实验。
- 不让卡卡自动覆盖实验代码或报告。
- 不把未经核实的数据集链接标为官方来源。
- 不在分享观察页里暴露项目群聊。
- 不把 AI 推断写成实测结论。
- RSI 自进化（56）不自动改代码、判据或报告，默认关闭、须人工批准、可回滚。
- 话题路由（58）不跨用户、不跨无权限项目，自动判定可被用户手动覆盖。
- ClawHub 外部技能（55）只导入 `SKILL.md` 文本，不执行任何安装脚本 / 代码、不代理 GitHub 托管技能字节；用量条（57）在规则模式下明确标注「本地估算」，不冒充模型真实用量。
